# 定时 Graph 邮件测试

“定时任务”位于侧栏“接码”下方。创建任务时输入邮箱关键词，浏览器会从当前账号池邮箱中提供补全选项；必须选择一个完整的已有邮箱。

间隔按分钟填写，最小值为 `1` 分钟。任务创建或编辑后，首次执行时间为当前时间加设定间隔。任务和执行记录保存在 SQLite 中，服务重启后继续调度。旧版本按小时创建的任务会自动换算为分钟显示，例如 `0.5` 小时显示为 `30` 分钟。

每次到期复用项目现有 Graph 测活流程：刷新 Microsoft Token、请求 `/me`，再发起一次邮件读取请求。测试结果会同时更新账号池的正常、ABUSE、Token 无效或其他错误状态。任务保存最近 10 条简短执行记录，页面展示最近 5 条。

编辑任务可以更换账号或间隔，并从保存时间重新计算下次执行时间。删除任务会同时删除该任务的执行记录；删除账号时也会删除关联的定时任务。

每个任务可以单独开启“BANNED 时发送 TG 通知”。当测活结果明确为 `health_status=banned` 时，任务立即停止，不会继续调度；Token 无效和其他异常不会停止任务。管理员处理账号后，可以编辑任务并勾选“启用任务”恢复。

Telegram Bot Token 和 Chat ID 在“设置 → 全局 API / TG”中配置。通知正文固定为：

```text
邮箱-banned-时间
```

Telegram 请求与 Graph 请求遵循同一代理设置；代理留空时直连。未配置 TG 或发送失败不会影响任务停止，失败原因会附加在该次简短执行记录中。

调度器在应用进程内以单个后台线程运行，每 30 秒检查一次到期任务。部署必须保持单 Uvicorn worker；当前 systemd 配置符合该要求。
